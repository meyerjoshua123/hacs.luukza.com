Setup guide & reference

This guide covers version 0.1.0, an early release. It describes what the integration actually does today, and marks what is still to come.

Install

  1. Make sure HACS is installed.
  2. In HACS open ⋮ → Custom repositories, add https://github.com/meyerjoshua123/ha-history-archiver and choose Integration.
  3. Download History Archiver and restart Home Assistant. HACS also installs its Python requirements (aiosqlite, openpyxl, pandas, pyarrow), so the first start can take a minute.
  4. Go to Settings → Devices & services → Add integration → History Archiver.

You can change both later under the integration's Configure.

The repository README lists services such as history_archiver.manual_export and backup_db. In 0.1.0 these aren't registered yet, so they won't appear in Developer tools. Until they are, query the database directly.

What's recorded

  • Which entities: every entity in your entity registry whose state is a number (sensors, numbers, input numbers…). Text states like on/off are skipped.
  • When: every record interval, one sample per entity with a UTC timestamp like 2026-09-27T03:15:00.123456.
  • Where: /config/history_archiver/history.db.
  • Metadata: each entity's device and area are kept up to date on every sync.

Storage size

Each sample is one database row, roughly 80–120 bytes including the index. Daily growth is about:

rows per day = numeric entities × (86 400 ÷ record interval in seconds)
Numeric entitiesIntervalRows / day≈ Size / day
10010 s864 000~90 MB
30010 s2 592 000~260 MB
30060 s432 000~45 MB
300300 s86 400~9 MB

On a Raspberry Pi or a small SD card, use a longer interval (60–300 s) and keep an eye on free space. There's no automatic clean-up yet.

Querying your data

Until exports are exposed, you can read the database with any SQLite tool, e.g. DB Browser for SQLite on your computer (copy the file off first), or the SQLite Web add-on. For example:

-- Hourly average of one sensor over the last day
SELECT substr(ts, 1, 13) AS hour, round(avg(value), 2) AS avg_value
FROM state_samples
WHERE entity_id = 'sensor.living_room_temperature'
  AND ts >= strftime('%Y-%m-%dT%H:%M:%S', 'now', '-1 day')
GROUP BY hour
ORDER BY hour;

-- Which entities take the most space
SELECT entity_id, count(*) AS samples
FROM state_samples
GROUP BY entity_id
ORDER BY samples DESC
LIMIT 20;

To trim old data by hand (stop Home Assistant or copy the file first):

DELETE FROM state_samples WHERE ts < strftime('%Y-%m-%dT%H:%M:%S', 'now', '-90 days');
VACUUM;

Exports (coming)

The export engine already in the code will write CSV, JSON, HTML, XLSX, SQLite, Parquet, Feather and Arrow, with optional downsampling:

  • Raw: every sample.
  • Mean: the average per interval.
  • Weighted mean: a time-weighted average, better for sensors that report irregularly.

Follow the GitHub repository for the release that exposes exports, profiles and backups.

FAQ

Does it replace Home Assistant's recorder?

No. It runs alongside it. The recorder powers Home Assistant's history graphs; History Archiver keeps its own evenly-spaced numeric samples for analysis.

Can it record text states such as on/off?

Not in 0.1.0: only numeric states are stored.

Does anything leave my Home Assistant?

No. The database lives in your config folder and nothing is sent anywhere.

Something isn't working

Please open an issue on GitHub with your Home Assistant version and any log lines mentioning history_archiver.
